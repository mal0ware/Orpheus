## Pin run (d): SED head selection

Generated by `scripts/pick_sed_head.py` on the reference RTX 3080, scored against the desktop fixture set (`~/.orpheus_fixtures`, 24 fixtures scored, `fixture_set_hash` `f941582f7b246bf718cebace52a383f82d81761eb611a541b0153dea6a713289`). Frame-F1 is micro-averaged (TP/FP/FN pooled across every 1 s frame of every scored fixture) per role and overall; truth-activity is `stem RMS > -50 dBFS` per 1 s frame (matching the Timeline hop). Only roles with a registry `tagger_classes` mapping are scored: bass, chords, drums.

Known scope limit: the installed `panns-inference` package loads only the `Cnn14_DecisionLevelMax` architecture regardless of the `head` string passed to `PannsTagger` (the Avg/Att checkpoints are not part of that PyPI distribution) -- all three candidate heads therefore run the identical weights/forward pass in this run, producing a genuine three-way tie rather than a fabricated split decision.

**Winner: `DecisionLevelAtt`** (three-way tie on overall F1 -- §15.6 breaks to `DecisionLevelAtt`)

Registry vocabulary fix applied before this run: `data/model_registry.json` gained `"Drum
machine"` in the `tagger_classes` of every entry that already listed `"Drum kit"` (the 7
drum-family entries: `4stem-a/bsroformer`, `4stem-b/scnet-xl`, `4stem-c/htdemucs-ft`,
`6stem/bsroformer-sw`, `6stem-fallback/htdemucs-6s`, `drumsep`, `drumkit-split/larsnet`).
This is the controller-mandated fix carried from Task 2.1's desktop evidence
(`tests/test_timeline.py::test_panns_tagger_detects_drums_on_ci_sparse`): this fixture
forge's sfizz/sample-rendered drum kit reads to PANNs as `"Drum machine"` (peak ~0.35) far
more strongly than `"Drum kit"`/`"Drum"` (peak ~0.04) -- without the fix, `drums` F1 above
would be driven almost entirely by the weaker classes and the drums column in `build_timeline`
would have been dropping the one AudioSet label doing the actual detecting. `"Electronic
drum"` was checked against `data/audioset_class_labels.csv` and does not exist in the
527-class AudioSet ontology, so only the one verified addition was made (conservative, 1 of
the allowed 1-3).

Honest caveat on the absolute numbers: `bass` and `chords` read 0.000 F1 (0 true positives)
and `drums` only 0.071 -- `fp` is 0 across every head/role, i.e. the tagger essentially never
crosses `CFG.TIMELINE_ACTIVITY_THRESHOLD` (0.30) for `"Bass guitar"`/`"Piano"` on these
synthetic sample-library stems mixed under a full 8-bar arrangement, and only briefly for the
drum family. That is a recall/threshold-calibration finding about this fixture material at
the current `# cal` threshold, not a Task 2.2 defect -- re-tuning `TIMELINE_ACTIVITY_THRESHOLD`
against this same truth data is `scripts/calibrate_gates.py`'s job (§16), out of this task's
scope. It does not change the head-selection outcome above: all three candidate heads see
byte-identical activations in this run (the known `panns-inference` scope limit noted above),
so the tie -- and the winner -- would hold regardless of where the threshold sits.
